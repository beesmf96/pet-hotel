# Flaky e2e test A6 fixed

## Asked
The backlog entry from the success-messages work: A6 ("daily overview shows
the changes") failed once and then passed on rerun.

## Done
- `changeDates()` in `e2e/support/owner.js` had two races, both found by
  logging the Livewire requests:
  - It returned right after clicking Submit. Filament hides the modal at
    once, so A6's next `page.goto()` could cancel the save.
  - "From" and "Closed" are live fields. A Submit click while the toggle's
    request was out was sometimes lost in the re-render, and no save was
    sent at all.
- It now waits for the form, then for each live field's request, then for
  the response to the save (`callMountedAction`). A new `invalid: true`
  option skips the save wait for A4 and A5, whose forms are meant to fail.
- The backlog's guess (wait for the modal to close) was wrong: it closes
  before the save. Recorded in the knowledge entry below.

## Not done
- A user would have to click Submit within a fraction of a second of
  toggling "Closed" to lose the click; not treated as a product bug.

## Produced
- ADR: none
- Knowledge: [filament-modal-submit-is-not-a-save.md](../knowledge/filament-modal-submit-is-not-a-save.md)
- Intake: none

## Verified
- Stress test (temporary, not committed): delaying only the save request by
  1.5 s made the old helper fail A6 3 of 3 times, with the original error
  (the 7 Nov row not "Closed"); the new helper passed 5 of 5.
- `bun run e2e e2e/a-owner-settings.spec.js --repeat-each=10`: 50 passed. An
  earlier version of the fix (save wait only) failed 1 of 25 on the lost
  click, which led to the live-field waits.
- `bun run e2e`: 23 passed. `bun run lint`: 0 errors, the same 5 existing
  warnings. No app code changed, so PHPUnit and Vitest were not re-run.
