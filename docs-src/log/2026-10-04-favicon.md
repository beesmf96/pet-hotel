# A real favicon for the site and both panels

## Asked
"Can we generate a favicon for this site?" The site had none: `public/favicon.ico`
was Laravel's 0-byte placeholder and no layout linked an icon, so every tab
showed the browser's blank page glyph.

## Done
- Design: a cream paw on a teal rounded tile, three toes and one pad. The two
  colours are the `--color-teal` and `--color-cream` values from
  `resources/css/tokens.css`. No outline and no hard shadow: at 16px both turn
  to mud. The mark was chosen from three sketches (paw, house-and-paw, animal
  head); the paw reads fastest at tab size.
- Assets: `public/favicon.svg` is the source of truth. `public/favicon.ico`
  carries 16, 32 and 48 pixel images for browsers that will not take an SVG.
  `public/apple-touch-icon.png` is 180px and deliberately **square with no
  transparency** — iOS applies its own rounded mask and composites anything
  transparent onto black.
- Tooling: `scripts/render-favicon.py` rebuilds the two raster files from the
  shapes. This machine has no ImageMagick, Pillow or librsvg, and none was
  added: the script is standard library only, supersampling 4x4 by hand and
  writing the PNG and ICO byte structures directly.
- Frontend: `resources/views/app.blade.php` links all three, ICO first then
  SVG, so a browser that understands both picks the SVG.
- Panels: both panel providers call `->favicon(asset('favicon.svg'))`. Filament
  emits one `<link rel="icon">` with no `type`, which every current browser
  sniffs correctly.

## Not done
- No `site.webmanifest` and no 192/512 icons. Nothing in the MVP asks to be an
  installable app, and they are more files to keep in step.
- The SVG and the shapes in the render script are two copies of the same
  geometry, kept in step by hand. A test pins the palette, not the shapes.
- No dark-mode variant. The teal tile already holds up on a light and a dark
  tab strip.

## Produced
- ADR: none
- Knowledge: none
- Intake: none — nothing was added that the project needs to run, build, test
  or deploy. The render script carries no dependency.

## Verified
- New `tests/Feature/FaviconTest.php`: the three files exist and are not empty,
  the ICO header really declares three images at 16/32/48, the SVG holds both
  token colours, the landing page carries all three link tags, both panels
  report the favicon URL, and the admin login page renders the tag.
- `composer test` in the app container: 402 passed, 1375 assertions.
  `vendor/bin/pint --test`: 164 files pass. No JS changed, so ESLint was not run.
- Served from the local Docker stack: `/favicon.svg` 200 `image/svg+xml`,
  `/favicon.ico` 200 `image/x-icon`, `/apple-touch-icon.png` 200 `image/png`.
  `/admin/login` and `/owner/login` both emit the icon link.
- The 16, 32 and 48 pixel renders were viewed before committing; the paw still
  reads as a paw at 16px.
